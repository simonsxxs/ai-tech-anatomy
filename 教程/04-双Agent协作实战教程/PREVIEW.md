## 00 先说清：你不需要写执行 Prompt

> 这本教程只讲一件事：你怎样用普通中文，让主 Agent 替你组织另一个 Agent 工作。任务书、测试命令、结果 JSON 都是主 Agent 自己生成和管理的材料。

![00 你不需要写执行 Prompt](pages/page-03.png)

## 01 第一步：告诉主 Agent 怎么分工

> 第一次使用时，你只需把「谁负责方案、谁负责执行、谁负责审查」说清楚——书里给了可以直接照抄的一句话。

![01 告诉主 Agent 怎么分工](pages/page-04.png)

## 02 第二步：先讨论方案，不急着执行

> 你可以先只说想法，不需要一上来讲清完整需求；你提问题，主 Agent 做调研、给推荐方向。

![02 先讨论方案](pages/page-05.png)

## 03 第三步：方案确认与实施批准，是两件事

> 「可以按照你的做」不一定等于「现在开始改代码」：方案确认只固化方案，批准执行才开始本地实施，真实支付 / 部署 / 发布必须另行明确授权。

![03 方案确认与实施批准是两件事](pages/page-06.png)

## 04 第四步：一句批准，主 Agent 开始派工

> 你批准之后，不需要写任务书、不需要开终端：执行 Prompt、子智能体提示词、任务书与命令都由主 Agent 自动整理。

![04 一句批准开始派工](pages/page-07.png)

## 05 执行期间：你可以继续做其他事

> 后台执行的意义：你不必一直等在当前对话里——可以讨论另一个功能、读阶段性结果、让其他会话做不冲突的任务。

![05 执行期间继续做其他事](pages/page-08.png)

## 06 结果回来：你只问这三个问题

> 不需要先读 JSON，也不需要懂测试命令：功能真的做好了吗？你实际看过、点过、测过吗？还有什么没做完？

![06 结果回来问三个问题](pages/page-09.png)

## 07 不满意：直接说哪里不对

> 你不需要替主 Agent 写返工 Prompt：只要指出你看到的问题和不希望扩大的范围，记录 FAIL → 定向修复 → 定向复验。

![07 不满意直接说](pages/page-10.png)

## 08 想更省事：让主 Agent 写全局规则

> 经常用同一种分工？让主 Agent 把这套工作方式写进全局 AGENTS.md：它起草，你审核确认，不需要学文件格式。

![08 让主 Agent 写全局规则](pages/page-11.png)

## 09 换成其他模型，说法不变

> 这套交互方式不依赖「Kimi＋ZCode」组合，替换角色名称即可，还可以按能力和成本搭配：能力较强的模型负责方案与质量审查，DeepSeek 等成本较低的模型承担规则明确的执行。

![09 换成其他模型说法不变](pages/page-12.png)

## 10 一页速查：你常用的几句话

> 分工、先出方案、批准执行、问结果、要求返工——每个场景一句可以直接复制的话。

![10 一页速查](pages/page-13.png)
