## 00 开始：先看懂一次完整协作

> 双 Agent 协作就是：一个 Agent 接收你的目标并负责检查，另一个 Agent 按任务书执行。你只需要做四件事：设定规则、给出任务、确认关键决策、查看结果与证据。

![00 开始](pages/page-03.png)

## 01 三个角色与委派时机

> “指挥”和“执行”是当前会话里的职责，不是某个产品永久固定的身份；三个角色各管什么、什么时候值得委派。

![01 三个角色](pages/page-04.png)

![01 委派时机](pages/page-05.png)

## 02 第一次委派：按这五步做

> 操作入口章：检查三个条件、写清任务、用短版 Prompt 启动、回复“批准执行”、等待执行并查看交接。

![02 五步做](pages/page-06.png)

![02 批准与交接](pages/page-07.png)

## 03 后台运行时，主 Agent 应该做什么

> 执行 CLI 一次接收任务、非交互运行；主 Agent 把长任务放到后台后，盯 task_id、读输出、不干等。

![03 后台运行](pages/page-08.png)

## 04 执行 Prompt 怎么写：六项内容缺一不可

> 给执行 Agent 的 Prompt 只要明确：身份与路径、任务与范围、验收标准、禁止事项、汇报格式、停止条件；复杂任务用 TASK.md + 短 Prompt。

![04 六项内容](pages/page-09.png)

![04 TASK.md 加短 Prompt](pages/page-10.png)

## 05 全局 AGENTS.md 怎么写，为什么更方便

> 把长期稳定的双 Agent 工作方式写进全局规则文件，一次配置、处处生效，不用每次重复交代。

![05 全局 AGENTS.md](pages/page-11.png)

## 06 命令与后台任务

> 主 Agent 应构造的调用命令示例：非交互执行、后台启动、读输出；参数以当前版本 --help 为准。

![06 命令与后台任务](pages/page-12.png)

## 07 多会话并行：避免文件与环境冲突

> 多开 Agent 前先判断能否并行：共享文件冲突、工作目录混用、浏览器空间混用和证据覆盖是四大坑。

![07 多会话并行](pages/page-13.png)

## 08 怎样验收：测试通过还不够

> 把四个层级分开：进程结束 ≠ 测试通过 ≠ 需求满足 ≠ 交付可信；发现 FAIL 后按记录—定位—修复—定向复验的循环处理。

![08 验收四层级](pages/page-14.png)

![08 FAIL 处理循环](pages/page-15.png)

## 09 指挥层与执行层怎样搭配

> 没有固定最佳组合：Kimi K3.1 Pro、Codex、Claude 都可以放在指挥层，GLM·ZCode、Codex 等都可以做执行，关键看当前任务。

![09 搭配建议](pages/page-16.png)
