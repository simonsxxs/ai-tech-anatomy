01

企业真正需要补什么

THE GAP

个人助手能把一件事做成；企业平台还要回答：谁能做、能看什么、谁批准、结果如何核对、出错怎样收住。

想象一个会读文件、写报告、调系统的“新同事”。把它介绍给全公司之前，需要给它工位、门禁、办事窗口和交接记录。这正是企业化设计要补的部分。

从个人使用走向团队新增的企业要求
一个人使用自己的资料统一身份；按用户、业务域和源文档判断权限
一次演示跑通重复请求、工具超时、撤权和恢复也有明确结果
看模型能不能回答能引用、能拒答；区分建议、待批和已经执行
个人承担调用费用部门预算、用量记录、资源准入和审计关联

本方案的四个设计取舍

决策选择与理由
D1 · 复用底座以 DSH 运行会话与工具；企业接入和治理围绕底座扩展。
D2 · 按用户与域隔离每用户 × 业务域一个逻辑实例，权限和回收粒度明确。
D3 · 业务受控接入业务系统经 MCP（模型上下文协议）接入工具；Skill（技能）描述方法，权限由服务执行。
D4 · 分批验证先知识库，再分别开放其他域和 IM；日期不能替代验收。
本文的范围这是一份可独立阅读的公开架构解剖。它讲清设计逻辑、能力边界和开工路径；完整部署蓝图及配套文档采用私有方式保存。

02

DSH 底座：大脑怎样持续办事

THE RUNTIME

DeepSeek Harness（DSH）是 Agent 的运行框架。它组织会话、模型与工具，让一次请求可以经过多步处理；企业身份和业务权限仍需接入设计。

底座机制可以复用什么企业仍需补什么
插件与会话组合能力、运行会话、持久化身份桥接、实例路由、版本治理
工具与 Skills调用能力、按需加载办事方法工具分级、业务审批、域包评审
子代理 / 工作流 / Goal委派、编排和继续执行持久任务台账、授权恢复与接管
网页界面 / 扩展槽位沿用原生界面并扩展面板角色能力、可信状态与界面验收

总体模型是单 Agent Loop、多用户多实例、每用户 × 业务域一个实例。域内可委派子代理，跨域按受控任务卡交接。子代理有自己的上下文与推理；具体消息和恢复能力应按所用实现核实。

已核实的来源官方说明确认 DSH 采用 Cordis 驱动的插件架构，仍处于开发者预览。本文关联蓝图基线为本机 core 0.2.1-rc.4；静态读取不代表企业环境已验收。来源见第 08 节。

03

五层架构：每一层负责什么

THE ARCHITECTURE

让运行、治理和业务接入各有负责位置，平台才能复用到不同企业和业务系统。

三个网关，处理三种问题

接入网关确认谁进入平台；MCP Gateway控制 Agent 调业务；模型网关适配模型协议、路由并计量。

控制平面与运行平面

控制平面管身份、位置和策略；运行平面负责具体会话。调度模块不因管理实例就自动获得全部正文访问权。

技术关系一句话DSH 负责运行 Agent；企业控制平面管理人和资源；MCP 连接业务能力；Skill 教 Agent 按业务方法做事。

04

一次经营报告请求如何完成

THE REQUEST

员工说：“整理我部门本月的经营情况。”平台要做的不只是把这句话发给模型。

状态用户应该看到什么
处理中 / 排队中当前进度、等待原因、取消或稍后查看入口
草稿 / 待确认结果和引用；明确还没有发送或写入
待审批操作内容、参数摘要、接收人、有效期和审批人
已完成 / 结果未知完成时有业务回执；未知时查询回执或转人工核对

如果员工接着说“把报告发给全部客户”，接收人和业务动作已经改变。需要登记新的操作意图，绑定具体参数与受众；执行前再次检查权限。对话恢复不能自动重放业务写入。

为什么需要持久操作台账人工审批可能跨越工具调用的超时时间。保存待批意图、审批和外部回执，才能在重试或重启后核对；外部超时且结果未知时，先查清再决定是否重做。

05

四个业务域，两个企业消息入口

THE BUSINESS

平台层负责共性能力；业务域包承载具体业务。换企业时，重点评估接口、资料、权限与验收条件。

业务域开放前要确认什么
办公 / 知识库资料 owner 批准人群；引用、拒答、源文档 ACL 与撤权通过。
数据分析仅开放批准的指标目录；验证行列权限、导出与大结果限额。
HR / 招聘候选人隐私和字段分级；敏感写操作审批，高敏数据单独处理。
客服 / 运营客户数据最小化；对外发送人工复核，区分建议与实际发送。

飞书、企业微信：分别验收，也要管住群受众

网页和私聊只有在身份、业务域、受众一致时才能续接。群聊有独立的会话与资料边界，不能继承私人上下文；附件与产物下载也要复核权限。两个 IM 分别验证消息来源、去重、回调、重连和审批交互。

对新业务的接入路径评估业务接口 → 封装 MCP → 设工具等级和权限 → 编写 Skill → 组装域包 → 受控验证。接入成本取决于现有接口和数据治理，不承诺任意系统零改造。

06

六个最容易被演示掩盖的边界

THE BOUNDARIES

企业保障要落在执行边界和可核对记录上。提示词可以指导行为，不能代替权限校验和结果核对。

容易混淆的事需要建立的工程规则
登录了，就能看全部资料？入口认证之后，仍要检查实例、会话、工具、文件和下载归属；普通用户不能统一升为高权限 owner。
有 Skill，就有操作权限？Skill 是方法。MCP Gateway 和业务端仍按当前主体、工具、参数、数据范围执行授权。
属于同部门，就能检索？遵守源文档 ACL（访问控制列表）；部门筛选不能替代文档权限，向量 collection 也不天然是安全边界。
审批通过，就能一直执行？审批绑定操作、参数、受众和有效期；过期、取消、撤权和目标变化后不得沿用旧授权。
恢复了会话，就恢复了任务？区分会话持久化、同步 checkpoint（进度点）、企业任务台账和外部回执；结果未知先核对。
模型兼容、费用和容量都已有答案？逐项验证实际 provider 协议；估算、用量和账单分开；容量使用真实 DSH 工作集测量。

撤权必须传播到旧连接和派生结果

员工离职或源文档权限改变后，还要处理旧连接、待批操作、缓存、索引、派生报告和下载链接。备份保留、恢复后的权限重建也要有规则。

Agent 犯错时谁来接住明确业务 owner、审批人、维护人和人工接管路径。保留关联记录，暂停受影响能力，核对真实结果，再决定修复和恢复。不能把责任仅交给一句“AI 可能出错”。

07

从哪里开工：技术选择与验证顺序

THE ROADMAP

先证明共性边界成立，再扩大业务范围。重组件随实际需要引入，十周估算不能变成自动上线承诺。

部分蓝图中的路线实施时核对什么
运行与工作台DSH core + 原生 GUI / 面板插件锁版本、受限身份、插件装载与真实状态
企业控制与业务接入FastAPI 服务、MCP Gateway、域包契约、身份传递、审批、幂等与回执
会话和企业数据会话文件 + PG + Redis + 对象存储事实来源、隔离、过期、备份与恢复
知识与模型pgvector + 独立向量化（Embedding）/ 模型适配源 ACL、质量、协议、数据范围和费用
编排与观测试点轻量容器编排 + 追踪 / 指标 / 日志工作集、准入、故障演练；再决定扩展

最低限度应留下三类验收证据

正向：有权用户完成请求并拿到引用或回执。
反向：跨用户、跨域、过期和撤权被正确拒绝。
异常：重复、超时、取消、未知结果、重启和恢复有明确处理。

先做有边界的小试点以批准资料和人群的办公知识库验证链路，再分别验收分析、HR、客服与双 IM。跨域长任务和规模化在持久任务、恢复、容量与成本证据成立后推进。

证据分层与进一步阅读

THE EVIDENCE

把“设计目标”“源码中存在”“局部探针通过”和“企业环境验收”分开，才知道下一步该补哪份证据。

证据层次本文能够说明的范围
公开一手资料DSH 官方说明与文档、MCP 授权规范。用于理解机制；上游可能变化。
本机静态读取关联蓝图使用 NEXT 2.0.21-next / core 0.2.1-rc.4 基线；不等于目标环境运行通过。
历史 W0 局部探针进程、合成数据、断网和部分槽位行为，各自只覆盖相应局部条件。
企业目标环境身份隔离、ACL、审批恢复、真实工作集、网络、双 IM 等仍须实施并补证。

普通 Node 进程的资源数字不能代替真实 DSH 容量；槽位注册不能代替完整界面验收。本篇没有重新运行这些测试，也没有发布部署程序。

公开源码阅读路线

先看整体：DSH 官方中文说明 → 官方文档。
再按问题：packages/core/agent-loop 看运行循环；packages/api/remote-access 看受限身份；packages/mcp/mcp-client 看工具调用；packages/llm/llm-deepseek 看模型协议。
理解工具授权：MCP 官方 HTTP 授权规范；传输层授权之外，还要实施具体业务权限。
